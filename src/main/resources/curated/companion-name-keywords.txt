# 식당 이름으로 동행 적합도를 추정하는 키워드 (2026-10-08)
# 팀이 직접 입력한 적합도(suitable_for_date 등)가 없는 식당에만 쓴다. 메뉴 종류에서 나온 추정일 뿐이라
# DB에는 저장하지 않고 추천 점수를 계산할 때만 참고한다. 적합이면 동행 가산점을 주고, 부적합이면 가산점만
# 주지 않는다(후보에서 빼지 않는다). 키워드가 없으면 "모름"이다.
#
# 형식: "동행유형 적합여부: 키워드, ..." — 동행유형은 CompanionType 이름, 적합여부는 GOOD 또는 BAD.
# 여러 키워드가 걸리면 가장 긴 키워드를, 길이가 같으면 이름에서 더 뒤에 나오는 키워드를 따른다
# (예: "곱창국밥"은 국밥, "갈비탕"은 갈비탕).
# 조명·뷰·좌석 간격·1인석처럼 메뉴로 알 수 없는 특징은 다루지 않는다. 후기 데이터가 쌓이면 그쪽으로 대체한다.

DATE GOOD: 파스타, 스테이크, 오마카세, 스시, 비스트로, 와인바, 브런치, 다이닝
DATE BAD: 국밥, 해장국, 감자탕, 뼈, 족발, 곱창, 분식, 김밥

SOLO GOOD: 라멘, 우동, 덮밥, 돈까스, 돈가스, 돈카츠, 국밥, 김밥, 분식, 버거, 카레, 쌀국수, 갈비탕
SOLO BAD: 삼겹살, 갈비, 곱창, 찜, 전골, 한정식, 오마카세
