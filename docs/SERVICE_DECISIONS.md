# 서비스 결정 — 2026-09-13

## 확정된 전시 범위

- 모바일 중심 웹앱. 검색은 사용자 현재 위치 기준 반경 5km 고정.
- 혜화 주변 식당은 팀이 직접 검수한 자료를 DB에 등록한다. 추천 결과를 코드에 고정하지 않는다.
- 등록 범위 밖에서는 데이터 부족으로 결과가 없을 수 있다. 서비스 전체를 혜화로 제한하는 것은 아니다.
- 후보 0개는 검색 결과 없음, 1~4개는 그대로 제공, 5개 이상은 상위 5개 제공.
- 후보 부족을 이유로 검색 반경이나 조건을 자동 완화하지 않는다.
- 기존 분위기 태그 8개와 자동 태그 추출은 폐기. 입력은 누구와 / 어디서 / 어떤 음식 중심.

## 동행 적합도

- 전시용 데이터는 팀이 직접 판단해 입력하며, 데이트·혼밥을 속성 조합으로 자동 추론하지 않는다.
- 적합도는 후보 제외 조건이 아닌 순위 가산점으로 사용한다.
- true는 적합 확인, false는 부적합 확인, NULL은 정보 없음으로 구분한다.
- false와 NULL에는 초기 가산점을 주지 않는다. 알 수 없는 값을 false로 채우지 않는다.
- 추론 전용 컬럼이나 자동 보정 로직은 지금 추가하지 않는다.
- Google 속성 매핑은 이번 수동 데이터 입력 경로에 포함하지 않는다. 향후 재검토 시 이용 조건과 출처를 확인한다.
- 데이트 / 친구 / 가족 / 혼밥 / 회식의 nullable boolean 5개 컬럼을 V2에 포함한다.
- 사용자 리뷰의 경험 카테고리는 별도 누적 데이터이며 현재 추천 입력과 구분한다.

## 미확정: 구현 전에 확인

1. 평점·거리 정규화 방식, 가중치, 동행 가산점 크기. 평점 비중이 거리보다 높다는 방향만 확정.
2. 평점의 출처·척도·미확인 값 처리와 동점 정렬 기준.
3. 식당 원본 자료, 좌표, 음식 분류 목록 및 사진·원문·출처 연결 방식.

## V2 구현 결정

- PostGIS geography(Point, 4326)와 GiST 공간 인덱스를 함께 추가한다.
- 위치는 기존 longitude / latitude에서 생성하는 저장형 생성 컬럼으로 동기화한다.
- 동행 값의 기본값은 두지 않는다. 기존 데이터도 미확인(NULL)을 유지한다.

자료가 제공되기 전 식당 데이터나 평점·적합도를 임의로 생성하지 않는다.
V1은 유지하고 합의된 변경만 V2 이후 마이그레이션으로 추가한다.
